title: Multimodal embedding
description: Turn text, images and video into vectors in one space.
---

Multimodal embedding turns text, images and video into vectors of numbers
in one shared space. A photo of cats and the words "cats asleep on a sofa"
get similar vectors, so one search finds pictures by a description,
descriptions by a picture, or both mixed together.

`createMultimodalEmbedder` runs Google's
[EmbeddingGemma 2](https://huggingface.co/google/embeddinggemma-2) and
returns vectors of 768 numbers. Text can be in 100+ languages or code.

## Quick start

```ts twoslash
import type { ImageBuffer } from 'runntime/zoo';
declare const catsPhoto: ImageBuffer;
declare const footballPhoto: ImageBuffer;
declare const streetPhoto: ImageBuffer;
// ---cut---
import { createMultimodalEmbedder, models, similarity } from 'runntime/zoo';

// 1. Load the model once. The weights download from the Hugging Face Hub.
const embedder = await createMultimodalEmbedder(
  models.multimodalEmbedding.EMBEDDINGGEMMA_2.DEFAULT,
);

// 2. Turn the photos into vectors.
const photos = await embedder.embedBatch([
  { image: catsPhoto },
  { image: footballPhoto },
  { image: streetPhoto },
]);

// 3. Turn a search into a vector and compare.
const query = await embedder.embed('cats asleep on a sofa', { task: 'query' });
photos.map((photo) => similarity(query, photo)); // [0.76, 0.55, 0.51], the cats match best

// 4. Free the GPU memory when done.
embedder.dispose();
```

The photos are two cats on a pink blanket, a football match and a street
crossing with cyclists. An image comes in as an `ImageBuffer`, the same as
in every vision task: `imageBufferFromImageData` reads one off a canvas,
see [Image classification](/zoo/image-classification/).

The engine must be set up first, see [Getting started](/zoo/getting-started/).

## Methods

```ts
function createMultimodalEmbedder(
  model?: MultimodalEmbedderModel,
  options?: LoadOptions,
): Promise<MultimodalEmbedder>;

interface MultimodalEmbedder {
  readonly dim: number;
  embed(input: EmbedInput, options?: EmbedOptions): Promise<Float32Array>;
  embedBatch(inputs: readonly EmbedInput[], options?: EmbedOptions): Promise<Float32Array[]>;
  dispose(): void;
}

type EmbedInput = EmbedPart | readonly EmbedPart[];
type EmbedPart = string | { image: ImageBuffer } | { video: readonly ImageBuffer[] };

interface EmbedOptions {
  task?: EmbeddingTask;
  dims?: number; // 768, 512, 256 or 128, default 768
}
```

- `embed(input)` turns one input into one vector, of `dim` numbers or of
  `dims` when the call sets it.
- `embedBatch(inputs)` does many inputs in one go, one vector per input in
  the same order. For text it is much faster than `embed()` in a loop.
- `dim` is the full length of a vector, 768. A call with `dims` returns
  fewer, see [Shorter vectors](#shorter-vectors).
- `dispose()` frees the GPU memory.

`similarity(a, b)` compares two vectors, see
[Text embedding](/zoo/text-embedding/#helpers). Any vector from the
embedder compares with any other, whatever each was made from.

## Inputs

An input is one part, or a list of parts that together make one vector:

- **text** - a string.
- **image** - `{ image }`, an `ImageBuffer`. It is resized to the token
  budget, see `imageTokens` below, keeping its aspect ratio.
- **video** - `{ video }`, its frames as `ImageBuffer`s in order. Pick the
  frames yourself, about one per second. Each frame takes at most 140
  tokens.

A list mixes them in reading order, like a product page with its text and
photos:

```ts twoslash
import { createMultimodalEmbedder, models, type ImageBuffer } from 'runntime/zoo';
declare const shoePhoto: ImageBuffer;
declare const solePhoto: ImageBuffer;
const embedder = await createMultimodalEmbedder(
  models.multimodalEmbedding.EMBEDDINGGEMMA_2.DEFAULT,
);
// ---cut---
const listing = await embedder.embed([
  'Waterproof running shoes.',
  { image: shoePhoto },
  'Grip on wet rock:',
  { image: solePhoto },
]);
```

An input must fit in `maxTokens`, 2048 by default. Each image or frame
counts its tokens plus two, so at the default budget an input holds at
least 7 images or 14 video frames. Text that does not fit is cut; an input
with images or video that does not fit is an error, thrown before any
image runs.

## Tasks

The model was trained with a short instruction before each text, and
`task` adds it. A search embeds its queries with `query` and what it
searches with `document`. The instructions are for text only, so embed
images and video without a task. In a mixed input the instruction goes
before the whole input.

```ts twoslash
import { createMultimodalEmbedder, models, similarity } from 'runntime/zoo';
const embedder = await createMultimodalEmbedder(
  models.multimodalEmbedding.EMBEDDINGGEMMA_2.DEFAULT,
);
// ---cut---
const query = await embedder.embed('cats asleep on a sofa', { task: 'query' });
const docs = await embedder.embedBatch(
  [
    'Two cats sleep on a pink blanket next to two TV remotes.',
    'A busy crossing with cyclists in a green bike lane.',
  ],
  { task: 'document' },
);
docs.map((doc) => similarity(query, doc)); // [0.78, 0.57]
```

| Task                | For                                                  |
| ------------------- | ---------------------------------------------------- |
| `query`             | search queries, compared with `document`             |
| `questionAnswering` | questions, compared with `document` passages         |
| `factChecking`      | claims, compared with `document` evidence            |
| `codeRetrieval`     | a description of code, compared with `document` code |
| `document`          | what a search searches                               |
| `classification`    | every text being classified                          |
| `clustering`        | every text being clustered                           |
| `similarity`        | every text being compared                            |

The first four go on one side of a search, `document` on the other. The
last three go on every text being compared. Without `task` a text gets no
instruction, which still works but matches less well.

## Shorter vectors

`dims` cuts the returned vectors to 512, 256 or 128 numbers, for less
storage at a small cost in quality, see the
[scores per length](https://huggingface.co/google/embeddinggemma-2#evaluation-results-with-vector-truncation)
on the model card. The model was trained so that the first numbers carry
the most meaning: a shorter vector keeps them and is made unit length
again. Compare only vectors of the same length.

```ts twoslash
import { createMultimodalEmbedder, models } from 'runntime/zoo';
const embedder = await createMultimodalEmbedder(
  models.multimodalEmbedding.EMBEDDINGGEMMA_2.DEFAULT,
);
// ---cut---
// A third of the storage.
const short = await embedder.embed('cats asleep on a sofa', { dims: 256 });
short.length; // 256
```

## Options

The first argument is the model config, a plain object with the fields
below. `models` holds ready-made ones: `DEFAULT`, the f16 weights run in
f16 where the device has `shader-f16` and in f32 elsewhere; `F16`, the same
files with f16 forced; `F32`, the f32 weights run in f32. Pass one as is,
copy it with a field changed, or point at your own files.

```ts
interface MultimodalEmbedderModel {
  readonly modelPath?: ModelPath;
  readonly visionPath?: ModelPath | null;
  readonly tokenizerPath?: string;
  readonly dtype?: 'f32' | 'f16';
  readonly maxTokens?: number; // default 2048
  readonly imageTokens?: 70 | 140 | 280 | 560 | 1120; // default 280
}

type ModelPath = string | RangeSource; // a URL, or bytes you already have
```

Examples:

```ts twoslash
import { createMultimodalEmbedder, models } from 'runntime/zoo';

// Text only: the vision tower is not downloaded.
await createMultimodalEmbedder({
  ...models.multimodalEmbedding.EMBEDDINGGEMMA_2.DEFAULT,
  visionPath: null,
});

// More detail per image, slower.
await createMultimodalEmbedder({
  ...models.multimodalEmbedding.EMBEDDINGGEMMA_2.DEFAULT,
  imageTokens: 560,
});
```

- **modelPath** - the text model's weights, a `model.safetensors` file.
- **visionPath** - the vision tower's weights, needed for images and
  video. `null` loads no vision tower: a smaller download for text only,
  and images and video become an error.
- **tokenizerPath** - the `tokenizer.json` file.
- **dtype** - `'f16'` or `'f32'`. `f16` runs the model in half precision,
  half the GPU memory, and needs a device with `shader-f16`. Default: `f16`
  where the device has it, `f32` elsewhere. Either loads any weight file.
- **maxTokens** - longest input in tokens, image and video tokens
  included, at most 2048.
- **imageTokens** - most tokens one image takes: 70, 140, 280, 560 or
  1120 tokens. More detail takes longer. Video frames always take at
  most 140.

Every field is optional. A missing one comes from
`models.multimodalEmbedding.EMBEDDINGGEMMA_2.DEFAULT`.

## Loading options

The second argument controls the download, the same as for every task:
`cache`, `onProgress`, `signal`. See
[Text embedding](/zoo/text-embedding/#loading-options). `onProgress`
counts the text model and the vision tower together.
